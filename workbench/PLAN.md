# 总计划：OASIS 设计文档治理与概要设计编制

- 编号：PLAN-001　版本：v1.2（2026-10-10，新增 §11 可检验性矩阵；对齐完成契约 G-001）
- 编制：设计开发　审定：质量管理
- 依据：用户任务指令（2026-10-10）

## 1. 目标

1. 清理、补充、完善 `docs/` 设计文档，使之**自洽、准确、干净**，形成单一权威基线；
2. 输出**完整的 LaTeX 概要设计说明书**（可编译 PDF，交付于 `docs/overview-design/`）；
3. 以四角色（设计开发 / 科学用户 / 评审专家 / 质量管理）分工与门禁方式组织上述工作，过程留痕可查。

### 1.1 质量准则（验收定义）

| 准则 | 判据 |
|:---|:---|
| 自洽 | 文档间、条目间、文档与图之间无矛盾；交叉引用全部可解析；术语与字段命名统一 |
| 准确 | 与 FITS / OIFITS 2 / astropy 等标准一致；字段、单位、错误码可验证；YAML 示例可解析并通过校验 |
| 干净 | 无死链、无过期路径、无重复来源（单一来源原则）；结构规范、目录整洁 |

## 2. 范围边界

- 纳入：`README.md`、`docs/` 全部设计与规范文档、PlantUML 图、工作台面与过程记录、新建 LaTeX 概要设计。
- 本任务不包含 OASIS 正式软件实现。为满足"设计—开发—测试—验收"闭环，开发/测试阶段以**可执行验证工件**（JSON Schema、YAML 样例、构建与一致性检查脚本）和**天文用例走查**为载体；同一门禁框架可直接沿用于将来的软件实现。
- Observables / Payloads 层在概要设计中按**接口级大纲**纳入；详细设计留待后续立项。

## 3. 方法论

- 设计开发：系统工程方法，自顶向下设计（系统 → 层 → 组件 → 接口 → 数据），自下而上测试集成（单元 → 集成 → 系统 → 验收）。
- 需求-设计-验证全程可追溯（追溯矩阵，`design/traceability/`）。
- 门禁：G1 方案设计评审（通过方可转入开发）；G2 测试报告评审（通过方可验收进入下一环节）。
- 质量管理独立监督，具叫停权；无门禁记录不得流转。

## 5. 门禁准则

**G1（方案设计报告）通过标准**

- 覆盖已识别科学需求（UR）并双向可追溯；
- 三项质量准则（自洽/准确/干净）达成；ICN 台账逐条闭环（A 级必须关闭，B 级关闭或有明确处置计划）；
- 评审意见无未闭环 A 类项。

**G2（测试报告）通过标准**

- 用例覆盖典型科学场景（含边界/异常场景），每用例具备明确预期与实测结果；
- 结论有证据支撑；未覆盖项与残余风险显式声明；
- 评审意见无未闭环 A 类项。

## 6. 天文用例方向（科学用户细化后冻结）

- UC-1 双星干涉观测：恒星模型 → 可见度/闭合相位预期
- UC-2 系外行星场景：光变 + 光谱组合观测模型
- UC-3 AGN / 吸积盘：多尺度图像 + 光谱
- UC-4 消光与各向异性背景：TransmissionModel + BackgroundModel 组合
- UC-5 参数扫描与正反演闭环：YAML 扫描输入 → 反演输入包 → 参数更新

正式用例条目须含：科学场景、输入样例、预期结果、通过判据。

## 7. 风险与对策

| 风险 | 对策 |
|:---|:---|
| 文档量大，修订引入新矛盾 | 修订后运行一致性检查（死链、术语、字段对照），检查结果留痕 |
| 无真实外部用户，需求来源单一 | 科学用户依据公开天文需求与标准文献，假设显式标注 |
| 同一代理扮演多角色，存在自证风险 | 强制产物-评审分离；评审意见引用条目；评审与验收环节可用独立子代理（全新上下文）执行；QM 抽查并记录独立性声明 |
| LaTeX 中文编译环境 | 已体检：XeLaTeX/latexmk/PlantUML 齐备；采用 XeLaTeX + ctex 方案，先做骨架冒烟编译 |
| 范围蔓延 | 变更走 QM 记录（QI/GR），重大变更报用户确认 |

## 8. 变更控制

本计划及基线的变更须经质量管理记录；A 类问题、门禁结论、范围变更必须留痕并可回溯。

## 9. LaTeX 概要设计说明书结构（初稿）

1. 引言（目的、范围、术语与缩略语、引用文件）
2. 系统概述（科学背景、系统目标、总体架构 TOP、用户与角色、运行环境）
3. 总体设计（设计原则、数据流、外部接口清单、约束与假设）
4. 目标层概要设计（三段式 V 型架构、组件职责、核心数据结构、内部接口 A–H）
5. 观测量层与载荷层概要（接口级大纲，后续细化）
6. 数据与文件格式（YAML、正演输出包、反演输入包、哨兵协议、OIFITS 衔接）
7. 非功能设计（性能、可靠性、安全、可维护性）
8. 接口控制摘要（错误码、版本策略、通信主题命名）
9. 需求追溯与验证（UR → 设计 → UC/TV 矩阵）
10. 附录（ADR 索引、术语表、参考标准）

引擎：XeLaTeX + ctex，`latexmk` 构建；图示由 PlantUML 导出后嵌入。
