## 2. 定义与作用域

- **数据集**＝经过发布的、可获取的数据产品；
- **清单（Inventory）**＝目标层内登记册，**管理动作唯一作用域**，仅收录发布型数据集；
- **派生品（Product）**＝镜像/同步/切片产物（manifest + QC），**不入清单**（裁决①），挂靠来源数据集；
- 作用域规则：未入清单不得触发任何管理动作；清单外需求走审核（F-07）。

## 3. 功能需求

**F-01 清单管理**：条目字段（id/名称/发布者/许可/渠道≥1/校验清单/版本规则/存储偏好/状态/审核记录）；
动作 propose/approve/reject/deprecate；追加式留痕；派生品永不入清单。

**F-02 发布渠道探测、连通性与版本确定**：DNS/连通性/HTTP 状态/Range/延迟/带宽；
版本由渠道元数据（Last-Modified/ETag/发布号/校验清单 mtime）推断；输出健康报告+版本表。

**F-03 远程↔本地镜像**：远程→本地断点续传（ssh+rsync 优先），版本未变 **0 下载**；
**本地→远程不做**（裁决④）。

**F-04 本地存储设备间同步**：storages 间（本机+ssh 目标）；默认 dry-run、`--apply`、**永不 `--delete`**。

**F-05 切片导出**：声明式参数 → 版本化派生品（manifest+QC）；首例 Gaia T1/T2/T3
（**细则移至设计阶段**，裁决⑤；需求要点见附录 A）。

**F-06 双 UI**
- 配置 + CLI（既有）；
- **Web UI**：本机 HTML5（仅 127.0.0.1）。**栈已确认：方案 A**——
  stdlib `ThreadingHTTPServer`（JSON+SSE+静态） + 前端 htmx 单文件（本地内置、无 CDN、无构建链） + SSE 实时；
  交互要点：dry-run 预览→确认执行；任务卡+实时日志（Last-Event-ID 重连+轮询回退）；渠道健康/版本徽章；
  审核收件箱；Web 与 CLI 共用同一内核与记账。
- **本地文件系统视图（追加需求）**：展示**本地设备在线/挂载状态**——
  挂载卷枚举（/Volumes）+ 与配置 storages 交叉引用；区分 **已挂载 / 已接入未挂载 / 未接入**；
  容量/可用/可写性；未注册设备提示；ssh 目标（NAS）"未探测/在线/离线"按需探测；
  Web v0.1 范围：清单浏览、任务发起/监控、审核、日志、**文件系统视图**；图表统计留后。

**F-07 审核机制**：propose → approve/reject（附意见）→ 入库/驳回；
**审核人＝项目负责人，单人确认**（裁决②）；CLI 与 Web 双入口；追加式留痕。

## 附录 A：切片导出首例——Gaia T1/T2/T3（需求要点，细则留设计阶段）

- 分档：T1 `G≤6`／T2 `G≤9`／T3 `G≤12`（`phot_g_mean_mag`）；缺失值丢弃并计数；
- 字段集：设计阶段定稿（要点：source_id/ra/dec/parallax/pmra/pmdec/phot_g_mean_mag/bp_rp 等）；
- 目录（草案）：`catalogs/gaia/t{1,2,3}/`（store 内）；
- 确定性：source_id 排序 + 原始值透传 + gzip `mtime=0` → 字节级可复现；
- manifest：沿用交付协议（provider=gaia_dr3、licence=ESA credits、version/epoch=快照）；
- QC：行数/门限统计 + 抽样回源 + 异常计数；随包 CREDITS.txt；
- 执行：单遍扫描同出三档；并行+断点续跑；8–16 路 ≈1.5–3 h；
- 规模（C0）：T1 数千级 / T2 ≈36–40 万 / T3 ≈530–580 万；合计 ≤1 GB。
  **实测修正（2026-10-11 全量导出 + 官方 TAP 交叉验证）**：T1=6,764 / T2=177,426 / T3=3,087,828，
  与 `gaiadr3.gaia_source` 官方 `COUNT(*)`（`phot_g_mean_mag <= 6/9/12`）逐行一致；
  C0 的 T2/T3 估算偏高约 2×，以实测为准；合计 236.5 MB（gz）；全量耗时 ≈67 min（8 进程）。
