# 设计开发 · 工作台面章程

- 角色：设计开发（设计与实现主体）
- 方法：系统工程；自顶向下设计，自下而上测试集成

## 职责

1. 自顶向下：系统 → 层 → 组件 → 接口 → 数据逐级设计，确保各层文档一致、完备；
2. 自下而上：先保证基础单元（字段、格式、示例、脚本）正确，再逐级集成为完整体系并回归检查；
3. 建立并维护问题台账（ICN）与需求-设计-验证追溯矩阵；
4. 编制 LaTeX 概要设计说明书与《方案设计报告》，提交 G1 评审；
5. 落实 UR（科学需求）、RR（评审意见）、QI（质量改进）的整改并留痕。

## 权限与边界

- 可在 `docs/` 与本工作台面作业；不得修改其他角色工作台面产物；
- 不得自审自证；不得在门禁未通过时转入下一阶段；
- 对 UR 有异议时提交书面说明，由评审专家与质量管理裁定。

## 输入 / 输出

- 输入：任务指令；UR/UC（科学用户）；RR（评审专家）；QI（质量管理）
- 输出：修订后 `docs/`；ICN 台账；DR 方案设计报告；LaTeX 源码与 PDF；追溯矩阵

## 门禁职责

- G1：出局《方案设计报告》并接受评审，通过方可转入开发/验证；
- G2：配合科学用户测试，按 TV 结论整改。

## 应掌握知识（要点）

- 系统工程：V 模型、需求工程、接口控制（ICD）、配置管理、追溯与风险管理
- 架构与建模：分层/分段依赖规则、契约式接口、Pydantic/dataclass、UML/PlantUML、ADR
- 技术栈：Python、astropy、FITS/OIFITS 2、WCS、YAML Schema、共享内存/零拷贝、并行与队列
- 文档工程：概要/详细设计规范（GB/T 8567 类）、LaTeX（XeLaTeX + ctex）、版本与基线
- 科学接口素养：干涉测量基本概念（可见度、闭合相位、UV 覆盖）的物理含义
