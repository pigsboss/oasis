# 附页 · 接口偏好与数据落地盘点

## 一、接口偏好：**文件为准、接口为线**

| 维度 | **文件（首选）** | 服务／socket |
|---|---|---|
| 可复算与审计 | **强**：字节可哈希、可归档，评审/质检可核同一份输入 | 弱：随服务状态漂移、归因困难 |
| 离线与批处理 | **强**：渲染可跑数小时—数天，不依赖对端在线 | 弱：服务一停链路即断 |
| 冻结与版本 | **强**：可随用户侧集成基线一起冻结 | 弱：缓存/版本混淆 |
| 体量 | **强**：百万行按文件传天然 | 弱：需自造流式/分页协议 |
| 与 oasis 设计一致 | **强**：其 TOP 层本就"**文件＋哨兵**"（`.forward_ready`／`.inverse_ready`） | 弱：服务层不在其设计中 |
| 实时/交互 | 弱 | 强（用户侧阶段 III 才需要） |

**接口契约建议**：

1. **主通道＝文件**：`catalogs/gaia/t1|t2|t3/…`、`catalogs/mpc/elements/…` ＋ **manifest**
   `id｜path｜bytes｜sha256｜version｜epoch｜provider｜licence`；传输用目录同步／rsync／tar 皆可；
2. **辅助通道＝薄 CLI**（不做常驻服务）：`oasis-catalog list / show / verify / fetch`；
3. **例外**：仅当用户侧进入**阶段 III 交互式可视化**或多用户共享时，再评估 HTTP 服务——**先文件、接口后置**；
4. **用户侧承诺**：**消费端只认 manifest** ⇒ 文件通道与将来的服务通道**切换零改动**。
