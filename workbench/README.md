# OASIS 四角色工作台面

本目录是「设计文档治理与概要设计编制」任务的四角色独立工作台面。
总计划见 [PLAN.md](PLAN.md)；各角色的职责、权限、交付物与门禁职责见各自 `CHARTER.md`。

## 角色与工作台面

| 工作台面 | 角色 | 定位 | 关键权限 |
|:---|:---|:---|:---|
| [design/](design/CHARTER.md) | 设计开发 | 以系统工程方法完成设计、修订与验证工件；出局方案设计报告 | 提交产物、发起评审 |
| [science/](science/CHARTER.md) | 科学用户 | 提出科学需求；以天文用例执行测试与验证；出局测试报告 | 判定科学满足性 |
| [review/](review/CHARTER.md) | 评审专家 | 独立评审方案设计报告与测试报告 | 门禁否决权 |
| [qm/](qm/CHARTER.md) | 质量管理 | 过程监督、门禁管理、改进闭环 | 叫停权 |

## 阶段与门禁

```
P0 基线盘点·审计·需求梳理 → P1 文档修订 → P2 概要设计/方案设计报告 ──G1──▶ P3 验证工件开发
                                                                        │
P5 验收与改进 ◀──────────── G2 ──── P4 科学测试与验证 ◀─────────────────┘
```

- **G1 方案设计评审**：通过方可转入开发/验证。
- **G2 测试报告评审**：通过方可验收，进入下一环节。
- 质量管理主持门禁检查，记录归档于 `qm/gate-records/`。

## 工作台面规则

1. 各角色仅在本工作台面内创建、修改产物；跨角色输入以引用与提交件传递，不混写。
2. 正式产物须包含编号、版本、日期、编制角色；修订递增版本。
3. 未经门禁（G1/G2）通过的产物不得作为下一阶段输入。
4. 质量管理有权在任何阶段要求补充履职证据、叫停流程；相关记录不得删除。
5. 交付物落盘：正式文档修订在 `docs/`；LaTeX 概要设计交付于 `docs/overview-design/`；过程记录留在本目录。
